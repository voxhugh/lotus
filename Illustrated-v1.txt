-------------------01-------------------【概述】
数据单元
  TCP段，UDP数据报，IP数据报，ARP分组，以太网帧

互联网
  internet: 用一个共同的协议族把多个网络连接在一起
  Internet: 世界范围内通过TCP / IP互相通信的所有主机集

IP分类
  8bit . 8bit . 8bit . 8bit
  --A--
  -----B------
  --------C---------
  note: 以上是各类的网络号长度

概念
  API: socket, TLI
  信源 = 发送方，信宿 = 接收方

行业简称
  二层 → 链路层
  三层 → 网络层
  四层 → 传输层
  七层 → 应用层

1小结
  网络层：提供点到点的服务
  运输层：提供端到端的服务
  每个主机的每个接口都有唯一IP，域名可以映射主机名到IP地址，端口号用来标识互相通信的应用程序，server使用知名端口，client使用临时端口
-------------------02-------------------【链路层】
链路层协议
  广播多路：以太网，802.3
  点对点：SLIP, PPP

MTU
  最大传输单元，指数据帧长度的上限
  路径MTU: 两台通信主机路径中的最小MTU

2小结
  环回接口 127.X.X.X
-------------------03-------------------【IP：网际协议】
IP首部
  大端字节序
  首部长度字段的单位是 4B
  TOS字段第1~4 bit 决定服务类型
  校验和字段只计算首部（16bit反码和），路由器的转发会减少TTL，故checksum逐跳校验

IP路由
  路由表存储IP（字段：目的IP，下一跳路由器IP，标志，网络接口）
  查路由表选路时 ①搜寻匹配IP ②搜寻匹配网段 ③搜寻默认路由
  路由选择是逐跳进行的，链路层目的地址是下一跳Mac，但数据报的目的IP始终不变

子网
  子网划分缩减了Internet路由表规模
  子网掩码是网络号与子网号的比特遮罩
  变长子网允许对子网进行再分，配套子网掩码

3小结
  主机发送数据报，路由器转发
  主机号为0时表示一个网段
  IP路由选择机制的强大特性是默认路由，以及ICMP间接报文
-------------------04-------------------【ARP：地址解析协议】
地址解析协议
  ARP的功能是动态映射IP地址到Mac地址
  点对点链路不使用ARP

ARP高速缓存
  存放了最近的 IP/Mac 映射，使用 arp -a 查看
  当系统收到ARP请求或发送ARP应答时，会把请求端的 IP/Mac 存入缓存

ARP分组格式
  ARP分组的字段围绕“硬件”和“协议”
  ARP请求里除目的Mac外的所有字段都有填充值

ARP请求/应答
  下一跳需要硬件地址，主机先自查ARP缓存，没有则发送ARP请求广播目标IP，目标主机应答自身Mac

ARP代理
  同网段但广播域隔离，需要代理应答ARP
  开启代理后，本机MAC应答该IP的ARP请求
  arp -s ip mac pub 设置强制代理

免费ARP
  主机广播自己的IP与Mac，用来检测冲突并通告更新
-------------------05-------------------【RARP：逆地址解析协议】
逆地址解析协议
  RARP是许多无盘系统在引导时用来获取IP地址的

RARP请求/应答
  RARP请求广播本机Mac，运行rarpd的主机应答该Mac对应的IP
  无盘系统取最先收到的RARP应答

5小结
  RARP分组的格式与ARP分组基本一致，帧类型、op不同
-------------------06-------------------【ICMP：Internet控制报文协议】
Internet控制报文协议
  ICMP传递差错与查询诊断信息

ICMP查询报文
  地址掩码应答，返回接收请求接口的子网掩码
  时间戳请求/应答用于测算往返时延

ICMP差错报文
  差错报文始终包含出错数据报的IP首部及其前8B数据（保证取到协议、IP、端口），所以能定位端到端的会话故障
  差错报文不会再触发新的ICMP差错，部分特殊地址报文同样不生成
-------------------07-------------------【Ping程序】
ping
  利用ICMP回显请求/应答测试两个TCP/IP系统的连通性

Ping程序
  在ICMP报文数据区存入发送时间，以此计算往返时间RTT
  首包RTT偏高，主要是本机ARP缓存缺失导致

IP记录路由选项
  途径路由器记录出口IP，应答信宿记录入口IP
  ping可启用RR，观测IP数据报对默认路由的使用
-------------------08-------------------【Traceroute程序】
Traceroute
  通过发送UDP数据报，自增TTL与无效目的端口，接收ICMP差错以追踪路由

traceroute局限性
  1. 探测间路由变动造成拼接路径失真
  2. 往返路径不对称导致RTT测不准
  3. 非对称路由仅得到单向探测快照

IP源站选路选项
  由信源指定途径节点，路由器读取清单，逐跳更新目的IP转发
  traceroute可启用LSRR、SSRR两种策略
-------------------09-------------------【IP选路】
路由表
  使用 netstat -rn 查看，字段包含 目的IP，下一跳IP，标志，接口
  Flags: U（路由可用），G（网关），H（主机），D（重定向创建），M（重定向修改）
  5bit标志，G区分直接路由和间接路由，H区分目的地是主机和网络
  选路机制 ①搜寻匹配IP ②搜寻匹配网段 ③搜寻默认路由
  网关即IP路由器，默认网关是默认路由的下一跳IP

ICMP重定向差错
  默认网关通知主机重定向，修改路由表

ICMP路由器发现报文
  主机启动后广播/多播发送路由器请求，路由器应答，每10分钟主动发送通告更新主机路由表
  通告有效期30分钟，超时失效
  可初始化并动态修改默认路由表项，区别于route配置的静态路由
-------------------10-------------------【动态选路协议】
动态选路
  路由守护进程运行于路由器，执行动态选路协议，例如routed, gated
  AS：自治系统。是同一管理域的路由器集合
  IGP：内部网关协议。用于AS内部选路，代表是RIP, OSPF
  EGP：外部网关协议。用于AS间选路，实际用BGP

RIP
  选路信息协议。距离-向量IGP，UDP封装，端口520
  地址族0，度量16 代表全路由表请求
  度量使用跳数，直连1跳，最大15跳，16代表不可达
  RIP-1：本地广播全路由表，直连邻居处理
  RIP-2：复用报文保留字段，支持多播

OSPF
  开放最短路径优先。链路-状态IGP，IP封装，协议号89
  探测邻站链路状态，信息域内扩散，各路由器独立计算得到路由表
  特性：以接口开销为选路依据，支持等价路由负载均衡；路由通告携带子网掩码，支持主机路由、默认路由；多播

AS拓扑分类
  残桩AS，多宿主AS，转送AS

BGP
  边界网关协议。距离-向量EGP，TCP封装
  与邻居交互路由信息，keepalive报文周期性检测邻站状态
  对外通告优选路由，支持人工策略干预选路

CIDR
  无类域间路由，又称超网。
  通过路由聚合缩减Internet路由表规模，以32bit 地址+掩码 运算，摒弃A/B/C分类
  聚合要求：地址高位一致，选路算法、路由协议均支持32位掩码
  选路策略是最长前缀匹配，优选掩码最长的匹配路由
-------------------11-------------------【UDP：用户数据报协议】
UDP数据报
  进程单次输出生成一个完整UDP数据报，交由IP封装，不保证可靠性
  容易触发ICMP源站抑制，无原生流量控制，需上层限流

UDP首部
  UDP校验和为可选，报文为奇数字节时本地补0参与运算，填充字节不发送，checksum端到端校验

IP分片
  IP根据出站MTU分片，终点重组，分片各自独立转发
  分片信息在IP首部第二个32-bit字
  任意分片首次到达，启动重组计时器
  除末片数据8B对齐，传输层首部在首片里，所以缺失无法生成ICMP重组差错
  信源不预分片，交由瓶颈路由器处理以减少碎片化

ICMP需分片差错
  DF=1 触发的ICMP不可达差错，携带下一跳MTU
  点到点链路双向MTU允许不同
  服务于PMTU-D（路径MTU发现机制），发送方置DF=1，依据差错调整MTU

UDP分片-ARP竞态
  UDP触发分片遇ARP缓存缺失时，会因邻居未解析队列限制丢包
-------------------12-------------------【广播和多播】
概念
  广播、组播仅适用于UDP
  单播送至单一主机接口，广播送至本网段全部主机，组播送至已订阅的主机

广播
  地址：高位划定域，域后置全1即为该域广播IP；LAN.Mac[47:0] := 1
  广播由IP层寻址，链路层执行群发投递
  分为本地广播、定向广播（网络，子网，所有子网）
  广播开销高，但适合在网段探测未知主机

组播
  地址：D类IP为组播IP；Mac[40] := 1, Mac[22:0] := IP[22:0]
  组播面向逻辑主机组分发报文
  组播地址算法映射，网卡仅粗筛，需要上层终检
  订阅是临时绑定，跨子网依靠IGMP维护组员
-------------------13-------------------【IGMP：Internet组管理协议】
Internet组管理协议
  IGMP由IP封装，仅限直连LAN，不做跨网段路由
  组播转发表提供候选出口，校验入接口防环，IGMP按登记状态过滤LAN出口
  使用 netstat -in 查看

IGMP报告和查询
  报告：进程选定接口订阅组，内核注册，本机经随机延时、同组抑制后发送报告，路由器登记转发表（IGMPv1退组不通告）
  查询：路由器周期性经各接口向224.0.0.1发出查询，主机复用延时-抑制逻辑应答来更新登记

特殊组IP
  224.0.0.0/24：本地组播。路由器不转发，IP按标准映射组播Mac，交换机默认泛洪投递
  224.0.0.1：所有主机组。本链路所有启用组播的主机自动订阅，等效LAN广播效果
-------------------14-------------------【DNS：域名系统】
域名系统
  使用倒置分布式域名树，自底向上书写
  反向解析独立挂载 in-addr.arpa 分支

DNS报文
  默认UDP，超长或区域传送时切换TCP，端口53
  在资源记录中用偏移指针压缩域名，Question段不压缩
  A(TYPE=1)域名查IPv4，PTR(TYPE=12)反向查询
-------------------15-------------------【TFTP：简单文件传送协议】
简单文件传送协议
  协议结构极简，可固化于ROM，用于无盘系统引导
  停-等协议，数据块从1编号，逐块ACK，0-ACK确认传输许可
  并发通过每客户分配独立临时端口实现，由UDP内核分流

TFTP报文
  UDP封装，端口69
-------------------16-------------------【BOOTP：引导程序协议】
引导程序协议
  无盘系统IP引导协议，RARP替代方案，DHCP技术前身
  客户端三层本地广播，服务端分配IP，三层广播应答，二层可选单播/广播，支持跨路由
  DHCP兼容BOOTP，使用变长选项并加入租期管理

BOOTP报文
  UDP封装，服务端口67，客户端口68
-------------------17-------------------【TCP：传输控制协议】
传输控制协议
  面向连接、可靠的字节流传输，点对点通信
  无应用层消息边界，全双工双向传输

连接标识
  Socket: IP + port
  Socket Pair: 全网唯一标识一条TCP连接

TCP首部
  首部长度单位为4B
  校验和机制同UDP，基于伪首部实现端到端校验

可靠性
  1. 应用字节流分段封装
  2. 超时重传
  3. 延迟确认
  4. 端到端校验和
  5. 乱序报文重排序
  6. 重复报文丢弃
  7. 滑动窗口实现双端流量控制
-------------------18-------------------【TCP连接的建立与终止】
概念
  确认号：ack = seq+Data+SYN/FIN，其中SYN/FIN是为了消除确认歧义
  seq：同步初始序号，划定单向流序号起点
  MSL：报文最大生存时间

连接
  三次握手
    C->S: seq = M                       | SYN
    S->C: seq = N,     ack = M+1 | ACK, SYN
    C->S: seq = M+1, ack = N+1 | ACK
  四次挥手
    C->S: seq = X,     ack = Y       | ACK, FIN
    S->C: seq = Y,     ack = X+1   | ACK
    S->C: seq = Y',    ack = X+1   | ACK, FIN
    C->S: seq = X+1, ack = Y'+1  | ACK

TCP选项
  MSS：单段最大载荷，仅SYN协商。一般取MTU-40，防止本机分片

TCP状态机（本端动作快照）
  CLOSED           无有效连接，无连接上下文
  LISTEN             端口绑定，被动监听，等待外部连接请求
  SYN_SENT       已发送SYN，连接上下文已创建
  SYN_RCVD      收到对端SYN，并回复SYN+ACK
  ESTABLISHED  本端握手完成，双向收发可用
  FIN_WAIT_1     本端已发送FIN
  FIN_WAIT_2     本端FIN已收到确认
  CLOSING         本端已发送FIN，收到对端FIN并回复ACK，等待本端FIN确认
  CLOSE_WAIT    收到对端FIN，回复ACK
  LAST_ACK        本端已发送FIN
  TIME_WAIT      所有FIN交互完成，等待2MSL计时

旧连接迟到包处理
  TIME_WAIT等待2MSL，socket pair暂不可复用
  TCP栈重启后MSL平静时间内不新建连接

复位报文
  首包异常RST的seq=0
  RST报文支持异常释放，替代FIN无需确认

特殊连接态
  半关闭：双向独立关闭，停发可收包确认
  半打开：单端已关闭/异常
  同时打开：互发SYN建立连接
  同时关闭：互发FIN，经CLOSING转入TIME_WAIT
-------------------19-------------------【TCP的交互数据流】
延迟ACK
  延迟数据确认，优先随反向报文捎带，减少独立确认报文

Nagle算法
  限一个未确认小段在途，缓存合并发送，抑制小段泛滥
-------------------20-------------------【TCP的成块数据流】
协议首部
  PSH=1，通知接收方尽快把数据交付上层，不必填满缓存
  URG=1，接收方提示应用优先读取，seq+ptr标记紧急数据末尾序号，读完解除紧急状态
  ACK累计确认，ack代表此前全部字节已收到

滑动窗口
  由对端ack与win共同界定发送许可区间
  合拢：左边界右移，收到确认
  张开：右边界右移，对端缓存释放
  收缩：右边界左移，通告窗口变小

拥塞窗口
  cwnd是发送方评估的网络承载上限

慢启动算法
  cwnd = 1*SMSS
  cwnd += 1*SMSS if new ack
-------------------21-------------------【TCP的超时与重传】
超时重传
  重传定时器只计时未确认报文，超时重传时RTO指数退避
  Karn算法：重传报文的ACK不更新RTT，持续使用退避RTO直到新ACK到达

拥塞避免算法
  cwnd += SMSS/cwnd if new ack

Reno拥塞控制
  if new ACK:
      if fast recovery:         cwnd = ssthresh              // 退出快恢复
      elif cwnd < ssthresh: cwnd += SMSS                // 慢启动
      else:                          cwnd += SMSS²/cwnd      // 拥塞避免

  if timeout:
      ssthresh = min(cwnd, win)/2
      cwnd = SMSS
  elif 3 dupACK:                                                       // ACK代表报文离开管道，快恢复膨胀响应管道负载下降
      ssthresh = min(cwnd, win)/2
      快速重传
      cwnd = ssthresh + 3*SMSS
  elif fast recovery and dupACK:
      cwnd += SMSS                                                  // 快速恢复
-------------------22-------------------【TCP的坚持定时器】
坚持定时器
  收到零窗口启动坚持定时器，周期性发窗口探查以防连接死锁

糊涂窗口避免
  接收方：窗口放大增量 Δ >= MSS or Buf/2
  发送方：发送数据长度 len >= SMSS or win/2，或 Nagle许可/无Nagle
-------------------23-------------------【TCP的保活定时器】
保活定时器
  可选机制，检测半打开连接，空闲发包判断连通性
-------------------24-------------------【TCP的未来和性能】
长肥网络
  带宽时延积大的网络称LFN，高带宽下时延与窗口是吞吐主瓶颈

TCP选项
  窗口扩大选项，仅SYN协商，收发移位因子允许不同

TCP性能
  协议理论上限由约1GB窗口与光速约束
